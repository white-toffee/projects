# 灵魂捕手：书架、阅读器与跨书剪贴升级 PRD

> 文档状态：Draft / 可用于后续产品设计、技术设计和 AI 辅助开发  
> 基线版本：灵魂捕手 0.2.0  
> 目标版本：0.3+，具体版本可按迭代范围调整  
> 最后更新：2026-08-19  
> 约束级别：本 PRD 描述产品目标、核心行为和数据安全边界；除明确标记为“必须”的部分外，技术方案均为建议，不限制开发团队采用更合适的实现。

---

## 1. 文档目的

本 PRD 用于指导“灵魂捕手”从单一碎片记录工具升级为 Markdown 书架、阅读器与跨文档剪贴组织工具。

文档面向：

- 产品经理与设计人员；
- 前端、Electron、文件系统及测试开发人员；
- 后续接手项目的 AI 编程助手；
- 需要理解产品边界、数据模型和验收标准的维护者。

后续实现应优先满足用户目标和数据安全要求。目录结构、框架、库、状态管理方案、Markdown 解析器及持久化实现可以调整，但应保留本 PRD 定义的产品语义。

## 2. 产品背景

### 2.1 当前 0.2 能力

当前版本已经形成以下闭环：

```text
监听或导入剪贴板
→ 收集文本/图片碎片
→ 选择与排序碎片
→ 在拼贴板编辑
→ 保存为 Markdown
```

已有能力包括：

- Electron Windows 桌面应用；
- 系统剪贴板文本和图片监听；
- 手动导入剪贴板；
- 当日碎片收集与 LocalStorage 持久化；
- 图片写入工作区 `images/`；
- 工作区文件夹选择与句柄恢复；
- 左侧碎片选择、删除和排序；
- 右侧拼贴、编辑、排序与 Markdown 保存；
- 剪贴板连接状态、操作日志；
- 单实例、窗口自适应、应用图标和 NSIS 安装包；
- test、lint、typecheck、build 质量链路。

### 2.2 当前问题

当前产品擅长“记录”，但尚不能有效组织工作区内已经存在的 Markdown 文档。用户需要在多个文件之间阅读、查找、抽取、移动和重新组合内容。

### 2.3 升级目标

升级后的产品应支持：

```text
收集碎片
→ 阅读已有 Markdown
→ 将文档拆成可操作的内容块
→ 在书内或跨书移动内容块
→ 从搜索结果及不同书中组织新内容
→ 命名并保存为新的 Markdown 文件
```

## 3. 产品愿景

灵魂捕手是一个基于本地 Markdown 文件的个人知识剪贴簿。

用户把工作区看作书架，把一个 Markdown 文件看作一本书，把标题、段落、列表、图片等 Markdown 内容块看作老式剪贴簿中的纸条。用户可以阅读、编辑、搜索和拖动纸条，并将不同书中的内容重新组织成一本新书。

核心价值：

1. 本地优先：用户的 Markdown 文件仍是最终数据源；
2. 内容可拆解：文章不是不可操作的长文，而是可组织的纸条；
3. 跨文档重组：内容可以在书、搜索结果和剪贴台之间流动；
4. 不破坏原文：所有写入、移动和冲突处理必须重视数据安全；
5. 兼容 0.2：现有收集功能继续可用，并成为新产品的收集箱模块。

## 4. 已确认的产品决策

以下决策视为当前产品基线：

| 编号 | 决策 | 规则 |
|---|---|---|
| D-001 | 一本书的定义 | 一个 `.md` 文件就是一本书 |
| D-002 | 文件夹的定义 | 工作区是书架；子文件夹是分类，不是书 |
| D-003 | 跨书拖拽 | 普通拖拽默认执行移动 |
| D-004 | 复制方式 | 建议使用 `Ctrl + 拖拽`执行复制；快捷方式可调整 |
| D-005 | 新拼贴保存 | 默认新建一本书，保存时由用户命名 |
| D-006 | 原书编辑 | 允许直接编辑，必须显示未保存状态并支持撤销 |
| D-007 | 剪贴台语义 | 剪贴台是一本尚未保存的新书 |
| D-008 | 0.2 定位 | 当前记录功能保留为“收集箱”，不被阅读器替换 |

## 5. 产品信息架构

### 5.1 顶层导航

建议的顶层结构：

```text
灵魂捕手
├─ 收集箱：现有 0.2 碎片记录功能
├─ 书架：工作区 Markdown 文件集合
├─ 阅读器：一本书的内容块阅读和编辑
├─ 剪贴台：跨来源内容的临时重组区
├─ 搜索：全工作区模糊搜索
└─ 设置：工作区、偏好、诊断等
```

具体导航样式不限，可使用标签、侧栏、页面路由或其他合理形式。

### 5.2 文件系统映射

```text
工作区文件夹
├─ A.md                     → 一本书
├─ B.md                     → 一本书
├─ 分类目录/                → 书架分类
│  └─ C.md                  → 一本书
├─ images/                  → 图片资源
└─ .soul-catcher/           → 可选的应用内部数据
   ├─ index.json            → 可选索引
   ├─ backups/              → 可选备份
   ├─ undo/                 → 可选撤销日志
   └─ sessions/             → 可选未完成剪贴台会话
```

要求：

- 必须兼容已有 `.md` 文件和相对图片路径；
- 不应要求用户迁移或重新导入现有文档；
- 内部状态不应污染用户 Markdown 正文；
- 内部目录名称和具体格式可以调整；
- 扫描时应排除应用内部目录和不相关隐藏目录。

## 6. 领域模型

以下是产品语义模型，不要求代码完全使用相同字段或命名。

### 6.1 Workspace

表示当前工作区/书架根目录。

建议属性：

- `id`
- `name`
- `rootPath` 或受限句柄
- `permissionState`
- `lastScannedAt`
- `bookCount`

### 6.2 Book

表示一个 Markdown 文件。

建议属性：

- `id`
- `path`
- `fileName`
- `title`
- `summary`
- `folder`
- `modifiedAt`
- `contentHash`
- `fragmentCount`
- `dirty`
- `conflictState`

标题解析优先级建议：

1. Markdown/YAML 中显式标题；
2. 第一个一级标题；
3. 文件名。

### 6.3 Fragment

表示书中的一个可操作内容块/纸条。

建议属性：

- `id`
- `type`
- `markdownRaw`
- `sourceBookId`
- `sourcePosition`
- `order`
- `createdAt`
- `modifiedAt`
- `contentHash`

支持的基础类型：

- `heading`
- `paragraph`
- `list`
- `quote`
- `code`
- `table`
- `image`
- `divider`

后续可以扩展任务列表、脚注、数学公式、嵌入内容等类型。

### 6.4 ScrapbookDraft

表示尚未保存的新书/剪贴台。

建议属性：

- `id`
- `name`
- `targetFolder`
- `fragments`
- `pendingOperations`
- `dirty`
- `createdAt`
- `updatedAt`

### 6.5 MoveOperation

表示书内排序、跨书移动或剪贴台暂存移动。

建议属性：

- `operationId`
- `mode`: `move` / `copy`
- `sourceBookId`
- `sourcePosition`
- `targetBookId` 或 `draftId`
- `targetPosition`
- `fragmentSnapshot`
- `createdAt`
- `status`

该模型应能够支持撤销、回滚和失败恢复。

## 7. 功能需求

### 7.1 收集箱模块

目标：保留并兼容 0.2 的记录流程。

#### FR-CAP-001 剪贴板捕获

- 应继续支持自动捕获系统剪贴板文本和图片；
- 应继续支持手动导入；
- 相同内容在规定时间内不应重复捕获；
- 图片应写入工作区资源目录；
- 捕获失败应提供明确提示和日志。

#### FR-CAP-002 收集箱碎片

- 应支持选择、删除、排序和编辑；
- 现有文本碎片可映射为 `paragraph`；
- 现有图片碎片可映射为 `image`；
- 不要求立即迁移现有 LocalStorage 数据格式，可通过适配层兼容。

#### FR-CAP-003 进入剪贴台

- 收集箱碎片应能够进入全局剪贴台；
- 是否保留现有勾选操作可以由交互设计决定；
- 不得破坏现有“收集后保存 Markdown”的基本能力。

### 7.2 书架模块

#### FR-LIB-001 扫描工作区

- 系统应发现工作区及子文件夹内的 `.md` 文件；
- 一个 `.md` 文件显示为一本书；
- 子文件夹显示为分类或筛选条件；
- 应排除应用内部目录；
- 文件增加、删除、重命名或修改后，书架应能够刷新。

是否使用实时文件监听、定时扫描或手动刷新由技术方案决定，但用户最终看到的数据应与文件系统一致。

#### FR-LIB-002 书籍展示

每本书建议显示：

- 标题；
- 文件名；
- 摘要；
- 修改时间；
- 碎片数量；
- 所属文件夹；
- 未保存或冲突状态；
- 自动生成或自定义封面。

第一版可使用统一封面模板和自动配色。

#### FR-LIB-003 书架操作

- 打开书；
- 新建空书；
- 按名称、更新时间排序；
- 按子文件夹筛选；
- 接收拖入的碎片；
- 刷新书架；
- 后续可扩展重命名、收藏、标签和删除。

### 7.3 阅读器模块

#### FR-READ-001 Markdown 内容块解析

系统应将 Markdown 解析为语义完整的纸条，而不是简单按换行拆分。

最低要求：

- 标题独立成块；
- 普通段落独立成块；
- 连续列表保持完整；
- 引用保持完整；
- 代码围栏及内容保持完整；
- 表格保持完整；
- 图片及说明保持合理关联；
- YAML Front Matter 不得被破坏；
- 未识别语法应尽量原样保留。

#### FR-READ-002 纸条展示

- 每个 Fragment 以老式剪贴簿纸条形式展示；
- 纸条应保留必要的 Markdown 语义；
- 应能识别纸条类型；
- 应支持定位纸条在原书中的上下文；
- 阅读大量内容时应保持可用性能。

#### FR-READ-003 原书编辑

- 用户可以编辑纸条；
- 用户可以新增、删除纸条；
- 用户可以在书内拖拽排序；
- 修改后必须显示“未保存”；
- 用户可以保存回原 Markdown；
- 用户可以撤销编辑和排序；
- 保存前应检查外部文件变化。

### 7.4 跨书移动与复制

#### FR-MOVE-001 默认移动

- 普通拖拽到另一书封面时，默认移动；
- 目标书应明确高亮；
- 放置提示应说明目标书和目标位置；
- 默认放到目标书最后；
- 后续可支持放到指定章节或位置。

#### FR-MOVE-002 复制

- 应提供复制而非移动的操作；
- 建议使用 `Ctrl + 拖拽`，但可以根据平台和交互研究调整；
- 界面必须让用户明确当前是移动还是复制。

#### FR-MOVE-003 跨文件安全

跨书移动必须满足：

- 来源书与目标书作为同一业务操作处理；
- 任一写入失败时不得留下半完成状态；
- 应支持回滚或恢复；
- 应支持撤销；
- 应检测外部修改冲突；
- 不得静默覆盖用户在其他软件中的更新。

实现可以采用临时文件、备份、操作日志或其他可靠方案。

### 7.5 剪贴台模块

#### FR-DRAFT-001 接收内容

剪贴台应能接收来自：

- 收集箱；
- 当前书；
- 其他书；
- 搜索结果；
- 用户新建的空白纸条。

#### FR-DRAFT-002 暂存移动

推荐行为：

- 从书中拖入剪贴台时，界面上视为已移出；
- 在新书正式保存前，不立即破坏来源文件；
- 取消或关闭剪贴台时，来源内容恢复；
- 应保留来源书和来源位置；
- 应能恢复意外关闭前的未完成剪贴台，或明确询问用户是否放弃。

如果开发采用其他安全且可理解的行为，应保持“取消不会丢内容”这一产品要求。

#### FR-DRAFT-003 编辑和排序

- 可以调整纸条顺序；
- 可以编辑内容；
- 可以删除或移出纸条；
- 可以新增空白纸条；
- 应能查看每张纸条来源；
- 应显示未保存状态；
- 应支持撤销。

#### FR-DRAFT-004 保存新书

保存时至少需要：

- 输入书名；
- 确定文件名；
- 选择当前工作区或子文件夹；
- 处理非法文件名字符；
- 处理同名文件；
- 写入新 `.md`；
- 更新所有发生移动的来源书；
- 刷新书架；
- 保存成功后默认打开新书。

默认书名建议：

1. 第一张标题纸条；
2. 否则使用“未命名剪贴”；
3. 同名时提示改名或生成安全的递增文件名。

### 7.6 搜索模块

#### FR-SEARCH-001 搜索范围

搜索建议覆盖：

- 文件名；
- 书名；
- Markdown 标题；
- 正文；
- 标签；
- 图片说明；
- 文件夹路径。

#### FR-SEARCH-002 模糊匹配

- 支持非完整关键词匹配；
- 支持对结果按相关度排序；
- 应在合理时间内返回结果；
- 工作区文件变化后，索引应更新。

具体搜索算法和索引技术不限。

#### FR-SEARCH-003 结果操作

- 搜索结果以碎片/纸条为主要展示单位；
- 显示来源书和上下文；
- 点击后跳转到原书位置；
- 可拖入剪贴台；
- 可拖到其他书；
- 可多选后批量移动或复制。

### 7.7 撤销与恢复

#### FR-UNDO-001 撤销范围

最低应覆盖：

- 书内排序；
- 跨书移动；
- 跨书复制；
- 删除；
- 编辑；
- 剪贴台添加、移除和排序；
- 新书保存带来的来源书修改。

建议至少保留最近 20 次操作，实际数量可根据实现和性能调整。

#### FR-UNDO-002 意外退出恢复

- 未完成的跨文件操作不应造成文档损坏；
- 未保存剪贴台应可恢复或安全放弃；
- 崩溃后应能识别未完成事务；
- 恢复失败时应提供备份位置和诊断信息。

### 7.8 外部文件冲突

#### FR-CONFLICT-001 冲突检测

编辑或移动开始时应记录文件版本信息，例如修改时间、大小或内容哈希。保存前再次检查。

#### FR-CONFLICT-002 冲突处理

检测到外部修改时不得静默覆盖。建议提供：

```text
《书名》已被其他程序修改。

[查看变化] [重新加载] [另存为]
```

后续可扩展自动合并，但不是第一阶段必需功能。

## 8. 关键用户流程

### 8.1 从收集到新书

```text
剪贴板捕获
→ 收集箱出现碎片
→ 选中或拖入剪贴台
→ 编辑与排序
→ 输入书名
→ 保存新 Markdown
→ 新书出现在书架
```

### 8.2 阅读和整理一本书

```text
打开书架
→ 选择一本书
→ Markdown 被解析为纸条
→ 编辑或排序纸条
→ 显示未保存状态
→ 保存原书
```

### 8.3 跨书移动

```text
打开来源书
→ 拖动纸条
→ 目标书封面高亮
→ 提示“移动到目标书末尾”
→ 放置
→ 安全更新来源书和目标书
→ 提供撤销
```

### 8.4 搜索后重新组织

```text
输入模糊关键词
→ 查看跨书纸条结果
→ 选择并拖入剪贴台
→ 调整顺序和内容
→ 命名
→ 保存为新书
```

### 8.5 取消剪贴台

```text
从多本书暂存移动纸条
→ 用户取消或关闭剪贴台
→ 提示确认
→ 所有内容恢复到原书和原位置
→ 不修改磁盘文件
```

## 9. 架构关系说明

### 9.1 逻辑模块关系

```text
                    ┌──────────────┐
                    │   工作区      │
                    │ Markdown/图片 │
                    └──────┬───────┘
                           │
                  ┌────────▼────────┐
                  │ 工作区/图书服务  │
                  │ 扫描、读取、写入 │
                  │ 冲突、事务、监听 │
                  └───┬────┬────┬───┘
                      │    │    │
             ┌────────┘    │    └─────────┐
             ▼             ▼              ▼
        ┌────────┐    ┌────────┐     ┌────────┐
        │ 书架    │    │ 阅读器  │     │ 搜索    │
        └────┬───┘    └────┬───┘     └────┬───┘
             │             │              │
             └─────────────┼──────────────┘
                           ▼
                     ┌──────────┐
                     │  剪贴台   │
                     └────┬─────┘
                          │
                          ▼
                     创建新 Markdown

剪贴板 → 收集服务 → 收集箱 ────────────────┘
```

### 9.2 0.2 与新模块的关系

| 0.2 能力 | 新架构中的位置 |
|---|---|
| 剪贴板监听 | 收集服务 |
| 左侧碎片列表 | 收集箱 UI |
| 右侧拼贴板 | 剪贴台的前身 |
| 工作区选择 | Workspace 入口 |
| Markdown 保存 | Book 创建能力的前身 |
| 图片保存 | 资源服务的前身 |
| LocalStorage | 临时会话与偏好，不作为书籍正文数据库 |
| Electron 外壳 | 保持不变的桌面基础设施 |
| `clipboardBridge` | 保持独立，不与图书文件 IPC 混合 |

### 9.3 建议的代码边界

以下目录仅表示推荐职责，可根据项目技术选型调整：

```text
src/
├─ domain/
│  ├─ book
│  ├─ fragment
│  ├─ scrapbook-draft
│  └─ operation
├─ application/
│  ├─ capture-service
│  ├─ library-service
```

### 9.4 桌面安全边界

建议继续保留：

- `contextIsolation: true`；
- `nodeIntegration: false`；
- `sandbox: true`；
- preload 只暴露有限能力；
- 渲染页面不能直接获得通用 Node 文件系统权限。

可以在现有 `clipboardBridge` 之外新增独立 `libraryBridge`，例如提供：

```text
selectWorkspace
scanBooks
readBook
saveBook
createBook
moveFragments
watchWorkspace
undo
```

接口名称和粒度不作强制要求，但必须限制所有路径在当前授权工作区内。

## 10. 数据一致性与安全要求

### 10.1 必须要求

- 不静默覆盖外部修改；
- 不因跨书移动失败而只修改其中一本书；
- 取消剪贴台不得丢失来源内容；
- 未识别 Markdown 语法应尽量原样保留；
- 所有文件路径必须限制在授权工作区内；
- 错误必须可见并可诊断；
- 重要写入应有恢复或备份路径。

### 10.2 建议实现

- 内容哈希检测版本；
- 临时文件写入后原子替换；
- 修改前备份；
- 工作区级写入锁；
- 事务日志或撤销日志；
- 崩溃后检查未完成操作；
- 图片和链接路径规范化。

具体实现不限，但验收时应验证失败和恢复行为。

## 11. 非功能需求

### NFR-001 性能

- 中等规模工作区打开书架时应保持交互可用；
- 大文档解析不应长期阻塞界面；
- 搜索应提供及时反馈；
- 文件变化应尽量增量处理；
- 图片和 Blob URL 应及时释放。

具体性能指标应在了解真实工作区规模后补充。

### NFR-002 可用性

- 默认窗口打开即可看到核心操作；
- 移动与复制状态必须明确；
- 未保存、保存中、保存成功、冲突和失败必须可见；
- 危险操作必须可撤销或二次确认；
- 高 DPI 下布局应保持可用。

### NFR-003 兼容性

- 优先支持当前 Windows Electron 桌面版；
- 必须兼容标准 Markdown 和现有 0.2 文件；
- 应尽量兼容用户同时使用其他 Markdown 编辑器；
- 不承诺第一阶段兼容所有 Markdown 方言。

### NFR-004 可测试性

- Markdown 解析和生成应可脱离 UI 测试；
- 文件事务、冲突和撤销应有自动化测试；
- UI 拖拽之外应有可直接调用的业务命令；
- 每阶段都必须运行 test、lint、typecheck 和 build。

### NFR-005 可维护性

- 不建议继续把新业务集中写入单一 HTML；
- UI、领域逻辑、文件系统和 Electron IPC 应逐步分离；
- 0.2 行为应通过兼容层或回归测试保护；
- 重构应分阶段完成，不要求一次性迁移所有代码。

## 13. 迭代建议

### Phase 0：0.2 稳定基线

- 固化当前安装包和回归测试；
- 明确收集箱边界；
- 保持当前用户流程可用；
- 为后续模块增加导航入口但不改变核心行为。

### Phase 1：只读书架

- 扫描工作区；
- 展示书籍；
- 支持分类、排序和刷新；
- 不修改 Markdown。

### Phase 2：只读阅读器

- 解析 Markdown；
- 以纸条形式展示；
- 验证各类 Markdown 往返完整性；
- 不开放写入。

### Phase 3：书内编辑

- 编辑、添加、删除和排序；
- 未保存状态；
- 保存、撤销和冲突检测。

### Phase 4：全局剪贴台

- 复用并升级现有拼贴板；
- 支持跨来源纸条；
- 支持命名并保存新书；
- 支持取消恢复。

### Phase 5：跨书移动

- 默认移动；
- 辅助复制；
- 跨文件事务；
- 回滚、撤销和崩溃恢复。

### Phase 6：模糊搜索

- 建立索引；
- 跨书纸条结果；
- 跳转与拖拽组织；
- 增量更新索引。

阶段可以合并或重新排序，但建议先只读、后写入，先单文件、后跨文件，以降低损坏用户 Markdown 的风险。

## 14. 非目标与暂缓项

以下内容不作为第一轮升级的必要范围：

- 云同步；
- 多人实时协作；
- 在线账户系统；
- PDF、Word 等非 Markdown 阅读；
- 完整替代 Obsidian/VS Code；
- 所有 Markdown 方言的百分之百兼容；
- AI 自动总结或生成；
- 移动端；
- 复杂自定义封面编辑器；
- 自动发布或博客托管。

这些能力可以在核心书架和剪贴闭环稳定后评估。

## 15. 开放问题

后续产品设计需要继续确认：

1. 工作区是否递归扫描全部子文件夹，是否允许排除自定义目录；
2. 书籍封面第一版采用自动模板还是允许图片；
3. 剪贴台未保存时关闭应用的具体恢复交互；
4. 跨书移动是立即落盘还是先进入统一待保存状态；
5. 撤销历史是否跨应用重启保留；
6. Markdown 方言优先兼容范围；
7. 是否保留原文格式，还是允许规范化格式；
8. 搜索结果默认移动是否需要额外确认；
9. 删除书、重命名书是否纳入 0.3；
10. 工作区内图片资源在跨书移动时是否移动、复制或只保留引用。

除非后续明确变更，本 PRD 推荐：跨书直接拖拽默认移动，剪贴台使用暂存移动，保存新书时再统一落盘。

## 16. 开发完成定义（Definition of Done）

每个迭代功能完成至少需要：

- 满足对应功能需求及验收条件；
- 不破坏 0.2 收集箱核心流程；
- 新增对应自动化测试；
- test、lint、typecheck、build 全部通过；
- 高风险文件操作具有失败和恢复测试；
- 用户可见的错误有清晰提示；
- 重要产品决策和架构变化更新到本文档或关联设计文档；
- 桌面开发版验证通过；
- 如涉及发布，安装包构建和启动验证通过。

## 17. AI 开发执行提示

后续 AI 或开发者处理本需求时，应遵循：

1. 先阅读本 PRD和当前代码，不假设尚未实现的模块已经存在；
2. 先确认当前迭代属于哪个 Phase；
3. 优先复用 0.2 的收集箱、拼贴板、工作区和 Electron 基础能力；
4. 不以大规模重写作为默认方案；
5. Markdown 解析与生成必须基于语义块，不按换行粗暴拆分；
6. 跨书移动默认是移动，复制是辅助操作；
7. 所有跨文件写入必须考虑冲突、回滚和撤销；
8. 不直接把整套书架正文存入 LocalStorage；
9. 不向渲染进程开放通用文件系统权限；
10. 每次实现只修改当前阶段所需范围，并补充对应测试；
11. 如果实现方案与本文建议架构不同，只要满足产品行为、安全边界和验收标准即可；
12. 遇到开放问题中会显著改变数据语义的决策时，应先向产品负责人确认。
